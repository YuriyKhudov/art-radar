# Telegram-журнал Art Radar

## Предпросмотр и повтор отбора

```powershell
python -m radar.telegram_journal preview --refresh --out journal-review/fresh
python -m radar.telegram_journal preview --snapshot journal-review/fresh/harvest.json --selection journal-review/fresh/selection.json --out journal-review/replay
python -m unittest discover -s tests -v
```

`index.html` показывает обложку, текст выпуска, прямые ссылки и хронометраж. `audit.html` показывает даты материалов, решения отбора, доли рубрик, материалы о любимых художниках и результаты сбора. `harvest.json` хранит метаданные площадок. `selection.json` фиксирует время отбора, историю и результаты проверок ссылок. `issue-1.html.txt` содержит готовую разметку Telegram.

Для точного повтора используйте оба файла от одного запуска вместе с теми же настройками и версией программы. Для объединения отдельных сетевых прогонов можно повторить `--snapshot`. Режим `--examples` остаётся доступен для хронологической симуляции с накоплением истории. [Код запуска и предпросмотра](../radar/telegram_journal.py)

## Редакционная политика

Поиск по любимым художникам и художественным направлениям работает поверх общего отбора. [Реестр, настройки и диагностика Artist Radar](artist-radar.md)

Ориентиры на 30 дней — 30% авторских видео и процессов, 25% практики, 20% новостей, 15% интервью, фильмов и историй, 10% архивных материалов. Счётчики предыдущих выпусков влияют на ранжирование вместе со свежестью, качеством и разнообразием рубрик. Обычный выпуск содержит 3–4 материала из разных издательств или авторских каналов. Каналы одного автора на разных площадках считаются одним источником. Свежий материал обязателен, видео получает приоритет. Окно — семь дней с приоритетом первых трёх. При нехватке материалов выпуск пропускается. Архив допускается только как редкое дополнение. Тематический выпуск можно собрать отдельно через `preview --theme`. [Параметры и источники](../editorial/sources.json) · [Правила отбора](../radar/editorial.py)

Описания опираются на конкретные детали из первоисточника. Фильтры пропускают короткие авторские ролики с видимым художественным действием и ролики проверенных авторов без хронометража, если сохранилось содержательное описание. Зарубежный материал ждёт, пока из источника удастся выделить и перевести содержательный фрагмент. [Правила обработки Artist Radar](artist-radar.md)

Обложка собирается из одного–четырёх оригинальных изображений с подтверждённым разрешением. Компоновка адаптируется к пропорциям, сведения об авторах и лицензиях указаны на обложке или в подписи. Если доступных изображений нет, используется типографическая обложка. Для локального предпросмотра установите Pillow. В личном тесте отправляется JPEG из проверенного предпросмотра вместе с подписью до 1024 символов. [Telegram Bot API](https://core.telegram.org/bots/api#sendphoto)

## Личный тест действующим ботом Art Radar

1. Откройте личный чат с действующим ботом **Art Radar** и нажмите **Запустить**. Если диалог уже открыт, отправьте боту личное сообщение, например `Тест Art Radar`.
2. В **Telegram Desktop** откройте меню `⋮` этого чата и выберите **Экспорт истории чата**. Выберите формат **JSON**, без медиа. В `result.json` найдите своё отправленное сообщение и поле `from_id` вида `user123456789`. Ваш Chat ID — цифры после `user`. Официальная справка описывает экспорт отдельного чата. [Экспорт в Telegram Desktop](https://telegram.org/blog/export-and-more)
3. В GitHub откройте **Settings → Secrets and variables → Actions → Secrets → New repository secret**. Создайте `ART_RADAR_TEST_CHAT_ID` со своим числовым ID. В режиме `private_test` используется существующий секрет `TELEGRAM_BOT_TOKEN`. [Секреты GitHub Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)
4. В **Actions → Журнал Art Radar → Run workflow** выберите `preview`. Для проверки нового оформления на прежнем выпуске укажите номер старого предпросмотра в `preview_run_id`. Откройте артефакт `art-radar-journal-preview` и проверьте выпуск. Скопируйте числовой ID нового запуска из адреса страницы `…/actions/runs/<ID>`. [Ручной запуск GitHub Actions](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)
5. Снова нажмите **Run workflow**, выберите `private_test` и введите этот ID в `preview_run_id`. Сверьте номер сообщения из результата с сообщением в личном чате. Проверьте обложку, переносы, даты и ссылки в клиенте Telegram. [Telegram Bot API](https://core.telegram.org/bots/api#getchat)

Перед отправкой `getChat` должен подтвердить точное совпадение ID и тип `private`. При отсутствии секрета или отклонении проверки вызова отправки не будет. Тест использует отдельную базу в ветке `art-radar-journal-test-state`. Повторная отправка того же выпуска блокируется, в том числе после запроса с неопределённым исходом. [Конфигурация запуска](../.github/workflows/telegram-journal.yml)

## Визуальный выпуск

Вариант `cards` отправляет три–четыре карточки по порядку и без звука. Первая содержит название, дату и слоган, остальные привязаны к ней ответами. Для оригинальной ссылки запрашивается крупных размеров нативное превью над текстом. Telegram определяет его внешний вид по данным площадки. Для разрешённых изображений используется вложение с атрибуцией. Кнопка всегда ведёт на оригинал. [Настройки превью](https://core.telegram.org/bots/api#linkpreviewoptions) · [Кнопки Telegram](https://core.telegram.org/bots/api#inlinekeyboardbutton)

Режим `native` использует нативные превью для всех карточек. Вариант `rich` объединяет фотографии, описания и кнопки в одно сообщение. Для него к каждой карточке требуется разрешённое изображение. Режим `both` отправляет `native` и `rich` в личный чат. [Единое сообщение](https://core.telegram.org/bots/api#sendrichmessage)

При включении плановой рассылки в новом журнале по умолчанию используется `cards`. Предыдущий формат доступен через `ART_RADAR_JOURNAL_FORMAT=legacy`. График остаётся один выпуск в три дня. После подтверждённого частичного запуска повторяются только оставшиеся карточки. Когда исход запроса неизвестен, в интерфейсе сверки укажите ID выпуска и подтвердите номер конкретного сообщения либо отсутствие карточки. После этого плановый запуск продолжит тот же выпуск.

## Хранение, расписание и запуск

Журнал использует отдельную SQLite. Сохраняются ежедневная выгрузка, выбранные материалы, даты и номера сообщений. После подтверждённой отправки следующий выпуск становится возможен через три календарных дня. Время по умолчанию — 19:00 мск. GitHub Actions проверяет срок каждые 30 минут. При задержке запуска проверяется один выпуск.

Перед вызовом Telegram SQLite с ожидающим выпуском сохраняется в отдельной ветке `art-radar-journal-state`. Перезапуск видит эту запись и удерживает отправку, пока результат предыдущей попытки не известен. Явный отказ Telegram оставляет возможность новой попытки со следующего дня. При неопределённом исходе `confirmed` записывает номер найденного сообщения, а `absent` применяется после проверки, что сообщения нет. [Воркфлоу журнала](../.github/workflows/telegram-journal.yml)

Расписание нового журнала включается переменной `ART_RADAR_JOURNAL_SCHEDULED=1`. Для отправки отдельно нужны `ART_RADAR_JOURNAL_PUBLISH=1` и секреты `JOURNAL_TELEGRAM_TOKEN`, `JOURNAL_TELEGRAM_CHAT`, `JOURNAL_TELEGRAM_TOPIC`. `ART_RADAR_JOURNAL_TIME` задаёт московское время. Перед согласованным переводом группы на новый процесс нужно отключить старое расписание Telegram. Известные ссылки предыдущих выпусков можно внести в `previously_published`.

Публичный сайт собирается отдельно раз в час из прежних RSS, YouTube и готовой статистики. Локальный сайт использует `data/radar.db` для продаж и лент. Избранное и просмотренные материалы сохраняет браузер. Прежний Telegram-процесс находится в собственном воркфлоу.
