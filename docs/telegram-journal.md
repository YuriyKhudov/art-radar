# Telegram-журнал Art Radar

## Предпросмотр и повтор отбора

```powershell
python -m radar.telegram_journal preview --refresh --out journal-review/fresh
python -m radar.telegram_journal preview --snapshot journal-review/fresh/harvest.json --selection journal-review/fresh/selection.json --out journal-review/replay
python -m unittest discover -s tests -v
```

`visual.html` показывает основной визуальный выпуск. `classic.html.txt` содержит разметку для совместимого текстового оформления. `audit.html` показывает даты материалов, решения отбора, доли рубрик, материалы о любимых художниках и результаты сбора. `harvest.json` хранит метаданные площадок. `selection.json` фиксирует время отбора, историю, проверку ссылок и проверенные редакционные тексты. Для проверки вёрстки можно задать `preview_urls`. Ранее показанные материалы можно исключить по `exclude_run_id`.

Для точного повтора используйте оба файла от одного запуска вместе с теми же настройками и версией программы. Для объединения отдельных сетевых прогонов можно повторить `--snapshot`. Режим `--examples` остаётся доступен для хронологической симуляции с накоплением истории. [Код запуска и предпросмотра](../radar/telegram_journal.py)

Режим `automatic_preview` в GitHub Actions собирает три разных выпуска последовательно из реальной выгрузки. Для проверки используется отдельный резерв в памяти. Ручные подборки, подготовленные тексты и привязанные к конкретным статьям изображения в этом режиме выключены. Предпросмотры `visual-1.html`, `visual-2.html` и `visual-3.html`, отчёт и исходная выгрузка входят в артефакт `art-radar-journal-preview`. [Воркфлоу журнала](../.github/workflows/telegram-journal.yml)

## Редакционная политика

Поиск по любимым художникам и художественным направлениям работает поверх общего отбора. [Реестр, настройки и диагностика Artist Radar](artist-radar.md)

Ориентиры на 30 дней — 30% авторских видео и процессов, 25% практики, 20% новостей, 15% интервью, фильмов и историй, 10% архивных материалов. Счётчики предыдущих выпусков влияют на ранжирование вместе со свежестью, качеством и разнообразием рубрик. Обычный выпуск содержит 3–4 материала из разных издательств или авторских каналов. Каналы одного автора на разных площадках считаются одним источником. Для новостей сохраняется семидневное окно с приоритетом первых трёх дней. Тематический выпуск можно собрать отдельно через `preview --theme`. [Параметры и источники](../editorial/sources.json) · [Правила отбора](../radar/editorial.py)

Ежедневный сбор пополняет резерв неопубликованных новостей, событий, уроков, открытий и архивных материалов. У события есть дата окончания или обычное семидневное окно. Подходящие события, уроки, открытия и фильмы сохраняются до следующего отбора. У выпуска из резерва сохраняется рубрика, а у более старых материалов появляется отметка о резерве или архиве. При нехватке система проверяет следующих кандидатов. Как исключение допустимы две сильные карточки из разных источников и с подтверждённым визуальным материалом. [Хранилище резерва](../radar/journal_reserve.py)

При нехватке полноценных карточек выпуск может дополнить рубрика «Из открытой коллекции». Она показывает лицензированные произведения из архива с русским названием, авторством и подтверждённой датировкой. Ссылка ведёт в каталог произведения. Прямой URL изображения и лицензия каждого файла сохраняются в карточке. [Правила каталожных карточек](../radar/journal_collections.py)

Описание ролика опирается на конкретные детали из первоисточника. Для текстового материала нужен полный открытый русский оригинал или указанная в `russian_editions` полная русская версия. Лиды из лент и переведённые выдержки помогают находить темы, но не проходят проверку полной статьи. Если нет доступа или доказательного изложения, кандидат исключается. [Правила обработки Artist Radar](artist-radar.md)

Открытые страницы загружаются в пределах каталога `article_domains` с учётом правил `robots.txt` и признаков платного доступа. Trafilatura извлекает основной текст. При первом вызове нужной редакционной обработки `ART_RADAR_RUN_LOCAL_EDITOR=1` запускает локальный llama.cpp с открытыми весами Qwen, закреплёнными по SHA-256. Модель составляет самостоятельный текст, указывает номера подтверждающих абзацев и выполняет отдельную проверку фактов. Код отклоняет слишком короткие, скопированные или формально неподтверждённые тексты. `article_edits` хранит отдельно проверенные редакционные тексты, которые действуют для конкретной контрольной суммы полного источника. Полный текст статьи не попадает в артефакты или историю. [Trafilatura](https://trafilatura.readthedocs.io/en/latest/corefunctions.html) · [llama.cpp](https://github.com/ggml-org/llama.cpp) · [Qwen](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)

Проверка иллюстраций идёт после первичной оценки кандидатов и до редакционной обработки текста. Для ярмарок и выставок нужны работы участников, для фотовыставок — художественные фотографии, для материалов о художниках — их работы, для техник — изображения процесса и результата или разрешённое видео, показывающее их. Для других художественных событий подходят подтверждённые виды экспозиции. Фасады, здания, улицы, случайные интерьеры и логотипы не служат заменой произведениям. Здания пригодны для материалов об архитектуре.

Иллюстрации приходят из метаданных первоисточника, открытых музейных коллекций, Wikimedia Commons и связанных официальных архивов. Поиск использует название работы, имя автора, тему события и подтверждённых участников. Для цифровой репродукции проверяются собственная лицензия файла, авторство и размер. Контрольная сумма сохраняется в предпросмотре и проверяется при отправке. При отсутствии разрешённого кадра у видео остаётся кнопка к ролику. Совместимый текстовый пост может использовать одно официальное превью Telegram. [Wikimedia Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo) · [Art Institute of Chicago](https://api.artic.edu/docs/#copyright) · [Telegram LinkPreviewOptions](https://core.telegram.org/bots/api#linkpreviewoptions)

## Личный тест действующим ботом Art Radar

1. Откройте личный чат с действующим ботом **Art Radar** и нажмите **Запустить**. Если диалог уже открыт, отправьте боту личное сообщение, например `Тест Art Radar`.
2. В **Telegram Desktop** откройте меню `⋮` этого чата и выберите **Экспорт истории чата**. Выберите формат **JSON**, без медиа. В `result.json` найдите своё отправленное сообщение и поле `from_id` вида `user123456789`. Ваш Chat ID — цифры после `user`. Официальная справка описывает экспорт отдельного чата. [Экспорт в Telegram Desktop](https://telegram.org/blog/export-and-more)
3. В GitHub откройте **Settings → Secrets and variables → Actions → Secrets → New repository secret**. Создайте `ART_RADAR_TEST_CHAT_ID` со своим числовым ID. В режиме `private_test` используется существующий секрет `TELEGRAM_BOT_TOKEN`. [Секреты GitHub Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)
4. В **Actions → Журнал Art Radar → Run workflow** выберите `preview`. Для проверки нового оформления на прежнем выпуске укажите номер старого предпросмотра в `preview_run_id`. Откройте артефакт `art-radar-journal-preview` и проверьте выпуск. Скопируйте числовой ID нового запуска из адреса страницы `…/actions/runs/<ID>`. [Ручной запуск GitHub Actions](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)
5. Снова нажмите **Run workflow**, выберите `private_test` и введите этот ID в `preview_run_id`. Сверьте номер сообщения из результата с сообщением в личном чате. Откройте одну работу из мозаики и проверьте текст, ссылки и воспроизведение видео. [Telegram Bot API](https://core.telegram.org/bots/api#getchat)

Перед отправкой `getChat` должен подтвердить точное совпадение ID и тип `private`. При отсутствии секрета или отклонении проверки вызова отправки не будет. Тест использует отдельную базу в ветке `art-radar-journal-test-state`. Повторная отправка того же выпуска блокируется, в том числе после запроса с неопределённым исходом. [Конфигурация запуска](../.github/workflows/telegram-journal.yml)

## Визуальный выпуск

По умолчанию `rich` отправляет одно сообщение с датой, слоганом и разделителями. Для мозаики передаётся до пяти отдельных изображений материала. Telegram размещает их с учётом пропорций. Для особенно узкого портрета или широкой панорамы используется отдельный блок. Вложения сохраняют пропорции. Разворачиваемый блок в конце выпуска содержит авторов, источники и лицензии. Статьи завершаются ссылкой «Читать оригинал». Под видео остаётся кнопка «Смотреть видео». Явно лицензированный MP4 с подтверждённого домена можно воспроизвести в сообщении. [Мозаика Rich Messages](https://core.telegram.org/bots/api#richblockcollage) · [Блок видео](https://core.telegram.org/bots/api#inputrichblockvideo)

Для старых клиентов можно выбрать `classic` в личном тесте или задать `ART_RADAR_JOURNAL_FORMAT=classic` для рабочей группы. Один обычный пост сохраняет все описания, прямые ссылки и атрибуцию. Этот формат применяется автоматически, если Bot API явно вернул `404` для `sendRichMessage`. Telegram не сообщает версию клиента каждого получателя и не принимает запасной текст в `sendRichMessage`. Если запрос завершился с неизвестным исходом, бот ждёт сверки. [Параметры метода](https://core.telegram.org/bots/api#sendrichmessage)

Выпуск выходит каждые три дня. Если результат запроса неизвестен, в интерфейсе сверки укажите ID выпуска и подтвердите номер найденного сообщения или его отсутствие. Старые ожидающие выпуски из нескольких карточек сохраняют свой порядок и номера сообщений.

## Хранение, расписание и запуск

Журнал использует отдельную SQLite. Сохраняются ежедневная выгрузка, выбранные материалы, даты и номера сообщений. После подтверждённой отправки следующий выпуск становится возможен через три календарных дня. Время по умолчанию — 19:00 мск. GitHub Actions проверяет срок каждые 30 минут. При задержке запуска проверяется один выпуск.

Перед вызовом Telegram SQLite с ожидающим выпуском сохраняется в отдельной ветке `art-radar-journal-state`. Перезапуск видит эту запись и удерживает отправку, пока результат предыдущей попытки не известен. Явный отказ Telegram оставляет возможность новой попытки со следующего дня. При неопределённом исходе `confirmed` записывает номер найденного сообщения, а `absent` применяется после проверки, что сообщения нет. [Воркфлоу журнала](../.github/workflows/telegram-journal.yml)

Перед переключением запустите `prepare_group` в **Actions → Журнал Art Radar**. Он проверит рабочую группу, права бота и создаст ветку истории при необходимости. Используется полный набор отдельных секретов `JOURNAL_TELEGRAM_TOKEN`, `JOURNAL_TELEGRAM_CHAT`, `JOURNAL_TELEGRAM_TOPIC`, а если он пуст — действующий комплект `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_THREAD_ID`. Возможность публикации в конкретную тему подтверждается при первой рабочей отправке.

Для перехода задайте `ART_RADAR_JOURNAL_SCHEDULED=1` и `ART_RADAR_JOURNAL_PUBLISH=1`. Старый воркфлоу пропустит отправку, когда обе переменные включены. Последнюю переменную включайте в день первого нового выпуска, спустя три дня после предыдущей публикации. `ART_RADAR_JOURNAL_TIME` задаёт московское время. Известные ссылки более ранних публикаций можно внести в `previously_published`.

Публичный сайт собирается отдельно раз в час из прежних RSS, YouTube и готовой статистики. Локальный сайт использует `data/radar.db` для продаж и лент. Избранное и просмотренные материалы сохраняет браузер. Прежний Telegram-процесс находится в собственном воркфлоу. [Сайт](../.github/workflows/site.yml) · [Старая подборка](../.github/workflows/telegram.yml) · [Локальные уведомления](../radar/notify.py)
