# Artist Radar

Artist Radar ежедневно дополняет общую редакционную систему. Предпросмотр и плановый выпуск используют один отбор. Сборка сайта и действующий Telegram-процесс запускаются отдельно. [Настройки журнала](telegram-journal.md)

## Автоматический поиск

Основной список проверяется ежедневно. Для остальных имён запросы чередуются по дням. Программа ищет публикации по русским и оригинальным именам в API художественных изданий. Поиск по направлениям также идёт в Art21, ARTandYou, OutdoorPainter и Painting Perceptions. В витрине открытий действует предел четыре автора на одно издание. [WordPress REST API](https://developer.wordpress.org/rest-api/reference/posts/) · [OutdoorPainter](https://www.outdoorpainter.com/) · [Painting Perceptions](https://paintingperceptions.com/)

По реестру `page_monitors` ежедневно проверяются официальные страницы художников, разделы выставок, авторский блог, галерейные каталоги и профильные публикации. Сбор учитывает `robots.txt`, ограничивает проверку разрешённым доменом и читает метаданные известных разделов. В SQLite сохраняются стабильный ID страницы, SHA-256 содержательных метаданных и даты первого и последнего наблюдения. В новости поступают записи с явной датой публикации из ленты, разметки статьи или издателя. Дата выставки и изменение каталога остаются в отчёте мониторинга. [Настройки источников](../editorial/artists.json) · [Сбор метаданных](../radar/artist_pages.py)

В отчёте есть запрос, площадка, количество ответов, ссылки на совпадения и ошибки. Для художественного открытия требуются имя в заголовке, подтверждение авторства в тексте и содержательная связь с тематикой. Кандидаты сохраняются отдельно от реестра любимых художников, с датами первого и последнего наблюдения.

Ориентиры 30/30/40 применяются после проверки качества, дат, доступности и повторов. Основной список получает больший приоритет, чем дополнительный и исторический. При отсутствии свежих материалов о любимых художниках выпуск собирается из других подходящих материалов. Подтверждённые авторские ролики могут попасть в выпуск без хронометража при достаточном описании и проверенной ссылке. Для иностранного видео дополнительно требуется подтверждённое русскоязычное сопровождение или явно описанный наглядный процесс и пригодная русская карточка.

## Русская редактура зарубежных материалов

Для свежих англоязычных публикаций программа выбирает одно или два соседних предложения, которые связывают автора с конкретной техникой, работой или процессом. Полученный перевод проверяется по языку, длине и сохранению чисел. Оригинальный фрагмент доступен в аудите. При отсутствии достаточных фактов или пригодного перевода карточка ждёт следующего сбора.

Журнал использует бесплатный анонимный MyMemory из облачного запуска. Лимит журнала за один сбор — 1600 байт публичных фрагментов, до 480 байт на запрос. Ранее полученный перевод сохраняется в выгрузке и SQLite. У сервиса анонимный лимит в 5000 символов в день. При исчерпании лимита или ошибках сбор остальных источников продолжается. Для автономного перевода на GitHub runner можно отдельно изучить Argos Translate. В текущей поставке используется существующая интеграция MyMemory. [Квоты MyMemory](https://mymemory.translated.net/doc/usagelimits.php) · [Условия MyMemory](https://mymemory.translated.net/terms-and-conditions) · [Argos Translate](https://github.com/argosopentech/argos-translate)

## Доступ и настройки

| Источник | Состояние |
|---|---|
| API изданий | Публичные запросы без ключа. Ответы и сбои видны в журнале поиска. |
| YouTube Atom | Открытые ленты известных авторов. Для части роликов атом-лента не передаёт длительность. |
| YouTube Data API | `JOURNAL_YOUTUBE_API_KEY` подтверждает хронометраж и добавляет до четырёх поисковых запросов за сбор для авторов, которых не покрыла подходящая лента. |
| RUTUBE | Публичные метаданные подтверждённых каналов. Используются исходные даты, длительность и плееры. |
| VK и VK Видео | Для автоматического чтения нужен `JOURNAL_VK_ACCESS_TOKEN` и доступ к видео нужного профиля через API. |
| Telegram, Instagram, Facebook | Ссылки предназначены для ручной проверки. Для автоматического чтения потребуются разрешения площадки и официальная авторизация. |
| Сайты художников, музеев и галерей | Автоматический сбор публичных разделов и наблюдение за метаданными. Сбои и страницы без даты видны в отчёте. |

## Команды проверки

```powershell
python -m radar.telegram_journal preview --refresh
python -m radar.telegram_journal check-platforms
python -m unittest discover -s tests -v
```

Предпросмотр собирает один выпуск и отчёт по каждому основному художнику. `check-platforms` проверяет доступ к публичным видео API. По расписанию GitHub Actions выполняет общий и именной сбор в одном задании журнала. [Воркфлоу](../.github/workflows/telegram-journal.yml)
